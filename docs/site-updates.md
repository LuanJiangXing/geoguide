# Site Updates

读到这个文件，意味着要写某一天的更新。无论你之前有没有读过这个文件，现在请依次读取接下来的所有文字，按上面的准则行动。

## Workflow

1. 先全量扫描最近的（默认当天，除非用户特殊要求）所有改动（git log、文件变更）
2. 按下方 guidelines 筛选排序、拟好条目
3. 先发给用户看，不要修改文件，不要commit
4. 用户确认后才写入 `public/data/changelog.json`

## Writing Guidelines

1. 每条不超过 15 个单词，5-10 个单词最佳。禁止长篇大论
2. 不出现任何 admin 相关内容
3. 之前没出现过的更新内容放更前面
4. 改动幅度更大、影响更广的内容放更前面
5. 概括简明，面向普通用户（非开发者视角）

## AI 自检清单（写 changelog 前必做）

1. 先发给用户看，不直接写文件
2. 总长 ≤ 15 词，多用名词短语
3. 普通用户语言，非开发者术语
4. 写完对照 changelog.json 已有的格式和词数
